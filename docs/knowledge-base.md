# 知识库设计

## 两层结构

```
packages/knowledge/
  data/            结构化规则(JSON,引擎直接命中)—— 主力
  src/             类型定义 + 查询函数
  corpus/ (后续)   清洗后的古籍原文(RAG,仅用于"引经据典")—— 锦上添花
```

**判断逻辑只依赖 `data/` 的结构化规则,不依赖 RAG 检索。** 文言文原文检索容易"检索到却用错场合",故只作出处增强,不参与判断。

## 古籍 → 结构化的映射

| 书 | 性质 | 最优用法 |
|---|---|---|
| **穷通宝鉴**(栏江网) | 查找表:日主 × 月令 → 调候用神 | 直接转 JSON 表(`qiongtong.json`)。ROI 最高,几乎零幻觉 |
| **滴天髓** | 原理 / 心法(赋 + 注) | 蒸馏成判断启发式(通关 / 调候 / 病药触发条件) |
| **三命通会** | 百科式(格局 / 神煞 / 十神) | 挖取格局定义与十神性情;不整本入库 |
| **紫微斗数全书 / 太微赋** | 星曜 / 四化 / 格局 | 安星规则交给 iztro;格局与四化解读蒸馏成规则 |

> ⚠️ 古籍**原文**属公有领域(ctext.org / 维基文库);现代**点校本 / 白话译注本有版权**,不得使用。

## 降低幻觉的杠杆排序

1. **确定性排盘引擎** —— 消除最大来源(算错节气 / 闰月 / 安星 / 起运)。
2. **结构化规则命中** —— 给解读提供准确的命理词汇与判断依据。
3. **古籍 RAG(可选)** —— 仅增强可信感与边缘案例,不决定判断逻辑。

## 数据文件约定

每个结构化数据文件带元信息:`source`(出处)、`version`、`reviewed`(是否经人工校对)。
未经人工校对的 AI 抽取数据,`reviewed: false`,在解读层需降权或标注。
